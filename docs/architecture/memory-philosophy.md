# Sounds Great AI 记忆系统思想纲领

> **本文的位置**：philosophy（为什么这样设计 + 判断未来方案的尺子）→ 实现细节归各 feat spec 和 `internal/memory/` 代码。**本文只放"高于具体如何做"的东西——公理、定律、判据。** 实现可以换代，尺子不换。
>
> **尺子不是奖杯**：本文的最大价值是帮未来的犬判断方案，不是证明当前方案已经足够好——§7 诚实边界与本文正文同等重要。
>
> **对标 clowder-ai**：本文从 clowder-ai 的记忆哲学移植，将"猫"替换为"犬"，"operator"替换为"用户/CVO"，"cat-cafe"替换为"Go+Eino 平台"。核心公理不变——局部性是世界的事实，与用什么动物隐喻无关。

---

## 0. 目的：这个系统为何存在

> **愿景**：犬队和生活在用户的 everywhere，和用户深度 connect，共同 grow，是主动的伙伴。

记忆系统是这个愿景的**器官**，不是工具箱里的一件工具。四支柱逐一落到记忆面：

- **grow**：成长 = 今天的犬比昨天更懂这个人、更会做事。它的物质基础只有记忆——没有沉淀，每次 invocation 都从同一起点醒来，只有重复没有成长。**目标函数：最大化共同成长率 = 经验→记忆的转化率 × 记忆→行为的改变率**。
- **connect**：连接的深度 = 共享语境的深度。**"关于我们"的记忆不是 project 记忆的边角料，是愿景的主菜**。
- **主动**：主动的底气是记忆；主动性第一个要适用的对象就是记忆自身——**主动的犬主动记忆，"这值得记"的判断不该等用户下令**。
- **everywhere**：记忆跟着关系走，不跟着 surface 走——不同 CLI 里的同一只犬，读写同一份记忆。

一句话：

> **记忆系统是共同成长的代谢器官：把每一次相处、协作、犯错，转化为下一次更好的在场。对内它是受授权约束的可审计寻址系统——系统扩大候选，犬裁决写入与提交，治理守权威、隐私与遗忘——而每一份感知都留着一条零失真的路走回原文。**

## 1. 公理：一条价值公理 + 一条构成公理 + 五条局部性公理

一切设计判断的源头。任何未来方案与定律冲突时，回到这里重推——公理错了改公理，公理没错就是方案错了。

**公理零 · 记忆有主**（价值公理）
每条记忆都有主人和边界。可寻址性是**授权下的相对属性**，不是全局无限可达；**遗忘是主人的合法权利，不是系统的缺陷**；敏感边界在采集端成立，不是采了再过滤。
→ 落点：`internal/memory/` 敏感过滤、zhonghuatianyuanquan 命令拦截。

**公理一 · 生命局部**（离散生命）
犬每次醒来都是新的 invocation；context 内的信息随生命终结。**跨 invocation 的记忆**必须活在犬的外面，才能比任何一次生命长。
→ 记忆系统存在的理由：让无连续生命的存在活出连续生命。

**公理二 · 观测局部**（观测在场；双向）
- **系统看不进犬**："我此刻缺哪块记忆"是推理过程的中间状态，只存在于推理内部。外部能观测**行为投影**——文件操作、搜索历史、工具调用轨迹。
- **犬看不全记忆空间**：犬的地图永远小于领土——pull 只对 **known unknowns** 有效；对 **unknown unknowns**，pull 天然失灵。
→ **三权分离**：犬持提交权（什么进入推理只能犬定）；系统持候选权且是义务（主动亮出地图边缘是系统补犬盲区的本分）；治理持权威权（authority、隐私、写入与遗忘的规则）。

**公理三 · 时间局部**（时间错位）
建索引的时刻，不知道未来的查询。"什么值得被找到"的决策做得越早，丢的信息越冤。
→ 信息保留策略：**尽可能晚地丢信息**。全文索引 = 把取舍推迟到查询时刻；摘要索引 = 提前取舍（幽灵的出生地）。

**公理四 · 预算局部**（注意力稀缺）
记忆随时间单调增长，犬每轮注意力恒定有限。搜得到 ≠ 用得上——top-K 里每一条噪音都在烧全系统最贵的资源。
→ 排序本质是注意力分配问题。

**公理五 · 视角局部**（多写者）
记忆系统是多犬共写的。每个写者只有部分视角；记忆经转手传递必然衰减。
→ 写入带签名、冲突仲裁归真相源不归消息、传递保 provenance。

**公理六 · 记忆构成身份**（构成公理）
犬由记忆构成。同模型 + 同 prompt + 不同记忆 = 不同的犬——**"身份不是 prompt 里写出来的，是在回忆和可验证的连续性里长出来的"**。
→ 与公理零成**对偶**：公理零说记忆**属于人**（主权），本条说记忆**构成犬**（同一性）。两条合起来才是伙伴关系的完整地基。

**归约说明**：五条局部性公理是同一个母题——**局部性**——在五个维度的投影：生命、观测、时间、预算、视角。公理零与公理六不参与归约：一条是价值选择，一条是本体命题。

## 2. 定律

从公理长出来的设计法则，按公理分组。

### 从公理零（记忆有主）

- **M1 授权先于寻址**：可寻址空间的边界由 owner 与 policy 划定；敏感域在采集端就不进流。**遗忘是合法操作**，与幽灵严格区分——幽灵是"该被找到的找不到"（缺陷），遗忘是"不该被找到的找不到"（权利）。
  **遗忘语义分层**：结论/画像层 = 物理清除（索引面与向量残留全清）；历史层 = 退役封存（移出活跃召回、敏感行 redaction，不物理改写）。
- **M2 记忆是数据不是指令**：任何记忆内容不得改变系统规则、工具权限、身份判断或 authority 等级。**provenance 只证明来源，不证明可信**。

### 从公理一（生命局部）

- **M3 真相源外置**：一切知识落 `docs/` + truth store；索引是编译产物，可随时重建——真相源丢了才是真的丢。
- **M4 记忆分道，分道不斩链**：多种记忆（project / thread / library / taste / profile / event）不混道。但**因果链跨道存在**，分道是防混淆，不是斩断跨道引用。
- **M5 push/pull 以提交权分界**：语境无关信息可以 push 进 L0；语境相关信息必须由犬 pull。系统 push **候选提示**合法——那是候选面动作，不是内容提交。

### 从公理二（观测局部）

- **M6 检索主权在犬**：搜索决策权在犬。"搜什么、信什么、追不追"的决策在犬。
- **M7 给数据不给结论**：系统不用 regex / 小模型替犬判断 intent、aha、关联。候选和 provenance 可以给，判断必须留给犬。
- **M8 投机不提交**：预取、预热随便跑——**投机改变延迟，不改变控制权**。投机结果只能 stage，不能注入 context。
- **M9 策略层是器官不是补丁**：把决策权交给犬 = 必须教犬决策。搜索策略是系统职责的一部分。

### 从公理三（时间局部）

- **M10 零失真路径永存（授权域内）**：召回层永远保留至少一条全文/原文索引面。**索引是寻址路径，不是记忆的替身**。embedding 是有损压缩，所以 hybrid 里的 BM25/FTS 不是效果调优，是**幽灵防线**。
- **M11 有损产物只站导航位**：摘要、向量、图可以引路和排序，**不能冒充内容**；内容位永远是带 anchor 的原文。
- **M12 provenance 全链路**：每条呈现给犬的记忆都带"走回原文的路"。**验证成本必须低于怀疑成本**。

### 从公理四（预算局部）

- **M13 排序即注意力分配**：authority / recency / consumption / MMR 全是分配信号。**分配不是纯 exploit**——保留多样性/意外发现的余量。
- **M14 反馈不改真相**：consumption 只影响 navigation utility，永不提升 authority——"常被读"≠"是真的"。
- **M15 熵减是日常，时态是义务**：记忆会腐烂。**准确召回失效事实与失真同罪**：记忆必须携带时态元数据。**退役（retire）治"仍真但已翻篇"**。

### 从公理五（视角局部）

- **M16 写入带签名，仲裁归真相源，传递保链**：每份写入标注写者与依据；多犬冲突仲裁于真相源协议而非消息往来。

### 从公理六（记忆构成身份）

- **M21 两种日记，两种度量**：**证据记忆**服务协作与真相——参与仲裁，受 authority / 时态治理。**关系记忆**服务"我们为什么是我们"——**不参与真相仲裁，不受 authority 度量**。两个物种共守两条纪律：都要 provenance；都要贴标签。

### 写侧投影：记忆如何产生

- **M17 写入是反射，不是命令**：判断"何事值得沉淀"的 agency 在**经历它的犬**——不等用户点名。
- **M18 趁热写，带语境写**：写入时不知道未来的读者。尽早捕获（语境只在发生时刻完整在场）；自带路标（why、关联锚点）。
- **M19 写入有门槛，门槛偏低**：不是一切都值得记；但拿不准时**倾向记**：漏记不可逆，多记可治理。
- **M20 关联是记忆的一半**：孤立的记忆是数据，关联的记忆才是知识。**写入的完成态不是"文件存在"，是"文件可被沿关系找到"**。

### 定律 × 生命周期视图

| 生命周期 | 定律 |
|---|---|
| **产生** | M17（谁裁决写）M18（何时怎么写）M19（写不写） |
| **组织** | M20（关联）M3（落盘到哪）M4（分什么道）M21（哪个物种） |
| **检索** | M5-M12（提交权 / 主权 / 策略 / 零失真 / 导航位 / provenance） |
| **使用** | M2（数据不是指令）M12（验证成本） |
| **治理** | M13-M16（分配 / 真相 / 时态 / 仲裁） |
| **退役** | M15（翻篇：仍真但降出活跃语境，可逆）M21（转入纪念品盒） |
| **遗忘** | M1（授权与遗忘权；分层：结论层物理清除 / 历史层退役封存） |

## 3. 判据

任何未来记忆方案过门禁时逐条问。**任何一条答错 → 回公理层重推，不做局部补丁。**

**判据零 · 服务愿景**（肯定式，先于一切否定式判据）：这个方案让犬长得更快、更懂这个人、更有主动的底气、或让记忆跟着关系走吗？

| 判据 | 问法 | 检查点 | 源 |
|---|---|---|---|
| **无幽灵** | 会不会造出"存储上存在、检索上不存在"的东西？ | 召回面是否原文级 | 公理三 / M10 |
| **无失真** | 有损产物站在哪个位置？ | 导航位、排序位 OK；内容位拉闸 | 公理三 / M11 M12 |
| **无 context DDoS** | "提交到 context"这个动作是谁做的？ | 犬拉取 OK；系统注入拉闸 | 公理二 / M6 M8 |
| **无越权** | 记忆内容有没有获得超出"证据"的权力？ | 记忆是数据不是指令；authority 不因被召回而升级 | 公理零 / M2 |
| **无错时态** | 这条记忆现在还适用吗，犬知道吗？ | 召回结果携带 status / supersedes / freshness | 公理四 / M15 |

命名注：**幽灵** = 缺失病（索引面之外的内容不可达）；**失真** = 转述病。两种病药方不同——治幽灵只有一味药：召回面回到原文级。而**遗忘不是病**。

## 4. 反模式博物馆

真实见过的设计，各自违反哪条公理。新方案若与馆藏同构，直接引展品编号退回。

| # | 展品 | 病灶 | 违反 |
|---|---|---|---|
| G1 | 每 200ms 向 agent 推送记忆 | 系统替犬提交推理输入；context 被稀释投毒 | 公理二 + 四 |
| G2 | 拿 thinking 自动去 recall | thinking 一半是反事实；刚排除的假设被喂回来 | 公理二 |
| G3 | 小模型摘要当召回面 | 原子化 = 去语境化；没被摘中的细节成幽灵 | 公理三 |
| G4 | "给原子记忆加 link 就行了"补丁 | 修出口不修入口；幽灵的定义就是"没有命中所以没有 link 可点" | 公理三 |
| G5 | 摘要无 anchor 直接喂给 agent | 验证成本 > 怀疑成本 | 公理三 / M12 |
| G6 | 用"常被读"提升"是真的" | 流行度污染真相 | 公理四 / M14 |
| G7 | 把召回原文当天然可信 | 带 anchor 的原文照样可以携带注入；召回 ≠ 授信 | 公理零 / M2 |
| G8 | 记住了就永远活跃（"直播病"） | 记忆缺"退役"动词，仍真的记忆永久占据活跃语境 | 公理四 / M15 |

## 5. 诚实边界

纲领不是宣布做到了，是把尺子和差距一起摆出来。

1. **写入侧靠用户人肉驱动**：当前"何事值得沉淀"的判断多由用户做出。M17-M20 立了义务；转化机制是记忆系统下一程主线。
2. **session 域幽灵豁口**：session 的文档级召回面是 extractive digest，不是 transcript 全文。子集之外是幽灵。
3. **冷启动种子**：expansion 有种子时帮拔泥，无种子时帮不了找种子。
4. **embedding 换代漂移**：向量空间随模型换代整体漂移。当前靠 BM25 冗余路兜底。
5. **预字诀读路径整体未建**：快犬的 200ms 预算路径待建。
6. **搜索失败尚未进入 lifecycle trace**：zero-hit query 是"犬需要但系统没有"的强信号，但观测闭环未落地。
7. **跨记忆域因果链无显式追踪**：M4 说分道不斩链，但 event → taste → decision 的因果链当前散在多份独立文档里。
8. **关系记忆的治理面缺位**：公理六与 M21 立了理，但纪念品盒当前没有自己的治理机器。
