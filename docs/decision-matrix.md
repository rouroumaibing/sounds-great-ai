# 决策矩阵

> 越宏观越关注，越细节越放手。

## 三层决策

| 层 | 谁拍板 | 触发条件 | 决策格式 | 举例 |
|----|--------|----------|----------|------|
| **宏观** | operator | 不可逆 / 愿景级 / 跨犬僵局 | Decision Packet（价值取舍题） | 砍整块 feat、开新 family、改 VISION |
| **中间** | 犬犬讨论 | 架构方向 / 技术选型 / 风险路由 | 先搜后问 + 证据论证 | 选 CLI adapter vs HTTP、选 RAG 后端 |
| **细节** | 犬犬自治 | 可逆 + 不碰硬排除 + 能翻代码 | 直接做 + 事后通报 | 改 bug、加测试、重构函数 |

## 可逆性判据

```
≤1 commit 回滚
+ 不影响外部用户/数据/契约
+ 不碰硬排除
→ 自决 + 事后通报
```

## 硬排除清单

| 排除项 | 说明 |
|--------|------|
| 愿景 | VISION.md §4 不可逆决策 |
| 权限 | auth / 角色 / 访问控制 |
| 生产数据 | internal/memory/、internal/ragstore/ 持久化数据 |
| production data boundary | 不指向生产用户数据 |
| 新外部依赖 | 引入新的第三方库/服务 |
| 契约 | API schema / MCP 工具签名 / CLI 输出格式 |
| 显著成本 | 大量 token / 长时间运行 / 金钱 |

## Decision Packet 格式

升级 operator 时必带，给**价值取舍题**不给技术 A/B 题：

```
## Decision Packet
- 价值取舍：X 还是 Y？
- 选 X 的代价：...
- 选 Y 的代价：...
- 我的建议：...（附理由）
- 可逆性：选错了能回滚吗？
```

缺 Packet = 打回。
